# 订阅链接：威胁模型与方案（v1 不实现）

"订阅链接"指 CFM 用"导入链接"通过 HTTPS 从门户拉取节点配置。v1 没有实现它，原因如下，最终要不要做、怎么做由运营者决定。

## 1. 现在的交付方式

按 Mooring 设计第 8 版（决策 F7、F9–F11）和《Mooring 使用约定》第 1 版：

- 配置**只以文件交付**：当面隔空投送，或 AES-256 加密磁盘映像，口令在 FaceTime 语音通话中念给用户；文件以 0600 生成，用户导入 CFM 后删除。
- `mooring-export` 要求用户已接受当前版本的使用约定，否则以 `AgreementNotAccepted` 拒绝导出。
- 使用约定第 5 条写明"本服务没有订阅链接"；用户指南第 3 步要求"不要用「导入链接」"。
- 服务器被封时，运营者按原方式重发文件。

这一套的要点：凭据从不出现在联网的服务器上；不留可转发的链接；每次交付都有运营者和用户的当面或语音确认。

## 2. 订阅链接会改变什么

| 变化 | 风险 |
|---|---|
| 节点凭据（UUID、REALITY 公钥与 short id、Hysteria2 密码）要放到联网的门户主机上 | 门户成了高价值目标：一旦被攻破，所有用户的凭据一起泄露，需要全部作废、重发 |
| 链接本身就是凭据（URL 里的令牌） | 会留在浏览器历史、CFM 配置、截图、聊天记录里，可以被转发；与使用约定第 2 条"不要把任何链接粘贴到聊天"相冲突 |
| CFM 定期回连门户拉取 | 门户域名和访问时刻暴露给用户所在网络；门户被封会连带影响更新 |
| 绕过了 `AgreementNotAccepted` 检查和语音确认 | 失去"每次交付都经过确认"这一环 |
| 使用约定第 5 条需要修订 | 所有用户都要重新确认新版本 |

## 3. 可选方案

**A. 不做（v1 的现状）。** 交付模型不变，门户只展示状态。代价：换节点时仍要人工重发文件。

**B. 登录后的一次性下载。** 用户登录门户，在运营者为其生成文件后下载一次，链接短时有效、用后即焚，下载前检查使用约定版本。文件仍需由 Mooring 生成后传到门户，凭据会在门户上短暂停留。比 C 的暴露面小，但仍改变了"凭据不上联网主机"的前提，也仍需修订使用约定。

**C. 真正的订阅链接。** 每个用户一个长期令牌，CFM 定期拉取。可以加的缓解措施：令牌可作废、可轮换；令牌只存摘要；按令牌限流；只返回该用户的配置；配置在门户上加密存储、密钥不在门户。但核心风险不变：联网主机持有全部凭据，链接可被转发。

## 4. 建议

v1 保持 A。如果换节点时的人工重发成了实际负担，优先考虑 B，并先回答：

1. 能否接受节点凭据出现在门户主机上（哪怕只是短暂停留）？
2. 门户放在哪台主机：伦敦 VPS、出口 Mac，还是另一台机器？这决定了门户被攻破时的影响范围。
3. 使用约定第 2、5 条怎么改，所有用户是否愿意重新确认？
4. 门户的域名会暴露给用户所在网络，可以接受吗？
