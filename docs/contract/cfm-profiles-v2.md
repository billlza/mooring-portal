# CFM 配置包契约，第 2 版

这是门户与 Mooring 之间的第二份数据通道。运营者在 Mooring 里点名全部已绑定门户账号的用户；Mooring 为其中可以交付的用户导出 CFM 导入文档，不交付的用户也写明，一起打成一个配置包。运营者在门户主机上用 `mooring-portal import-profiles` 导入。门户把每个用户自己的文档交给他：订阅页上可以下载，也可以生成订阅链接让 CFM 拉取。

- 实现：`crates/core/src/profile/`（解析与校验）、`crates/store/src/profiles.rs`（导入）、`crates/web/src/pages/cfm.rs`（下载与拉取）
- 金样：`contract/fixtures/cfm-profiles-v2/`（`valid/` 合法配置包，`invalid/` 每条规则至少一个反例）
- 金样测试：`crates/core/tests/contract/profiles.rs`
- 与第 1 版的区别：第 6 节

## 1. 与快照的区别

快照（`portal-snapshot-v1.md`）不含任何凭据。配置包则**含凭据和节点地址**：VLESS UUID、REALITY 公钥与 short id、Hysteria2 密码与混淆密码、节点 IP。所以它是单独的一份文档、单独的导入命令和单独的表，快照的导入和传输不因此多带凭据。门户：

- 只检查文档的外形（第 3 节），不解读、不改写、不派生任何字段；
- 原样保存 Mooring 写下的文本，原样交给 CFM（逐字节，有测试）；
- 任何错误信息、日志和 `Debug` 输出都不引用文档内容。

配置包只含运营者点名的用户，也就是已绑定门户账号的用户（运营者 2026-11-06 决定：「只导出已绑定用户」）。没有门户账号、只用文件交付的用户，凭据不经过门户主机。

## 2. 配置包

一个 UTF-8 JSON 对象，最大 1 MiB。每个键都必须出现，出现未列出的键即拒绝。

| 键 | 类型 | 含义 |
|---|---|---|
| `format` | 字符串，恒为 `"mooring-portal-cfm-profiles"` | 防止把快照或别的 JSON 误当配置包导入 |
| `version` | 整数，恒为 `2` | 契约版本 |
| `generated_at` | Unix 秒 | Mooring 生成配置包的时刻 |
| `profiles` | 数组，可以为空 | Mooring 交付的用户，每用户一项，见下表 |
| `withheld` | 数组，可以为空 | 运营者点名、但 Mooring 这次不交付的用户，每用户一项，见下面第二张表 |

`profiles` 的每一项：

| 键 | 类型 | 含义 |
|---|---|---|
| `user` | 字符串 | Mooring 用户编号（10 个小写 base32 字符，与快照相同；别名会被拒绝） |
| `document` | JSON 对象 | 该用户的 CFM 导入文档，即 `mooring-export` 以默认格式 `ExportFormat::SingBoxJson` 写出的内容 |

`withheld` 的每一项：

| 键 | 类型 | 含义 |
|---|---|---|
| `user` | 字符串 | Mooring 用户编号，规则与上表相同 |
| `reason` | 字符串，取下表之一 | Mooring 为什么不交付 |

| `reason` | Mooring 一侧的事实 |
|---|---|
| `"suspended"` | 被暂停，无论原因（运营者暂停、超额、到期、滥用审查）：节点不再为他服务，凭据保留，恢复后原来的文档又能用 |
| `"revoked"` | 作废中或已作废（`RevokePending`、`Revoked`，与快照一样都写作 `revoked`）：凭据已删除或正在删除 |
| `"agreement_not_accepted"` | 状态正常，但还没接受当前版本的《使用约定》：节点照常服务，Mooring 不为他导出文件 |

其他取值一律拒绝（金样 `invalid/unknown-reason.json`）。暂停的细分原因（例如 `quota_exceeded`）不进配置包：快照的 `status` 里已经有（`portal-snapshot-v1.md`），订阅页按快照显示。

## 3. 规则

违反任何一条，整份配置包被拒绝，什么也不写：

1. 先读 `format` 和 `version`，不认识的格式或版本单独报出。
2. 至少点名一个用户：`profiles` 和 `withheld` 不能都为空。同一个用户只能出现一次，无论在 `profiles` 里、`withheld` 里，还是两边各一次。
3. 每份 `document` 最大 64 KiB，并且是 sing-box 节点列表：一个对象，**唯一的键**是 `outbounds`，它是非空数组，每一项是带非空字符串 `type` 和 `tag` 的对象。其余字段由 CFM 判断，门户不检查。

第 3 条正是 CFM 0.5.1 导入器把文档交给"受限 sing-box 适配器"的条件（Mooring `docs/cfm-contract.md`，"How CFM reads an export file"）：带 `inbounds`、`route` 等键的完整 sing-box 配置会被 CFM 拒绝，门户在导入时就拒绝它（金样 `invalid/full-sing-box-config.json`）。Clash YAML 等其他格式 CFM 也能导入，但本契约只收 JSON 节点列表（`invalid/clash-yaml-as-text.json`）。

出错时只报种类和位置（第几行第几列），不报解码器原话：解码器的信息会引用出错的值，而那可能是一份文档或其中的凭据。格式不对时，只认得出门户快照，其他格式一律说"另一种格式"，不复述文件里写的格式名（有测试，包括把整份配置包、单个条目放进字符串，或把文档放进 `user`、`withheld` 编号里的几种畸形）。

## 4. 导入

`mooring-portal --db <文件> import-profiles <配置包>`：

- **每一个已绑定账号的 Mooring 用户都必须被点名**，在 `profiles` 里或 `withheld` 里都算。有已绑定账号没被点名，多半是运营者导出时漏列了：整份配置包被拒绝，什么也不改，错误里列出这些账号的编号和 Mooring 用户。运营者应当重新导出、把他们也点上；只有确实不再为某个账号服务时才解绑它，因为解绑会删除它的配置和订阅链接。漏列因此不会被当成停止服务，也不会让谁的订阅链接停用（有测试，包括同一份配置包还把一个有链接的账号列入 `withheld` 的情形）。
- 点名齐全时，配置包是**已绑定用户的完整集合**：导入后，门户只保留 `profiles` 里已绑定用户的文档，其余已存的文档全部删除。
- `withheld` 里的已绑定账号此后没有配置，订阅链接也在同一个事务里停用，不论原因；之后的配置包再交付该用户，旧链接也不会恢复，用户要重新生成（有测试）。命令逐个报出这些账号和原因，并注明谁的链接就此停用。暂停和未确认约定虽然是暂时的，也照此永久停用（运营者 2026-11-06 决定：「保持永久停用」）：恢复服务后，用户在门户重新生成链接，再在 CFM 里重新导入。原因只写进导入报告；以后若改为只暂停链接，只改门户，不改配置包的格式。
- 点名了、却没有绑定任何账号的用户（运营者列错了人，或者导出之后解绑了），什么也不保存，命令分两种报出：在 `profiles` 里的，凭据已经随配置包经过了门户主机，命令提醒立即删除配置包文件；在 `withheld` 里的，配置包没带他的凭据，只提醒下次别再点名。
- `generated_at` 比门户主机时钟晚 300 秒以上：拒绝。比上一次导入的配置包早：整份拒绝。同一份可以重复导入。
- 检查和写入在同一个立即事务里完成，别的命令在这期间绑定或解绑账号，要等导入结束。写到一半失败时整个事务回滚，配置、链接和配置包时间都不变（有测试）。
- 解绑或删除账号时，该账号的文档和订阅链接随之删除（外键级联，有测试）。

## 5. 交付给用户

两种方式，内容完全相同，都是 `Content-Type: application/json`、`Content-Disposition: attachment; filename="moorlight-cfm.json"`、`Cache-Control: no-store`、不压缩：

- **下载**：`GET /subscription/profile.json`，按登录会话取该账号自己的文档。
- **订阅链接**：`GET /sub/<令牌>`，供 CFM 的「导入链接」和「更新」使用。令牌规则见 `docs/security.md` 第 9 节。

CFM 0.5.1 拉取链接时的行为（`release/0.5.1` 的 `apps/cfw-tauri-shell/src/commands/subscriptions/fetch.rs`）决定了门户必须满足的条件：

| CFM 0.5.1 | 门户 |
|---|---|
| 只接受 `https`，主机须是公网域名或公网 IP，URL 不超过 2048 字符，不带用户名密码 | 链接是 `--origin` 加 `/sub/` 加 64 个十六进制字符；部署时 `--origin` 必须是公网 HTTPS 域名 |
| 发送 `Accept-Encoding: identity`，任何其他 `Content-Encoding` 都拒绝 | 不压缩响应 |
| 只接受 2xx，正文非空、UTF-8、不超过 4 MiB | 200 时正文是文档（不超过 64 KiB）。失败一律是纯文本：令牌未知、格式不对、已停用或账号没有配置都是 404，超过限流 429，数据库出错 500，不是 GET 或 HEAD 是 405 |
| 最多跟随 5 次重定向，每一跳都重新校验 | 不重定向 |
| `User-Agent: clash.meta cfw-rs/0.5.1` | 不按 User-Agent 区分，永远返回同一种格式 |
| 已连接时经自己的本地代理拉取，未连接时直连 | 无需配合；未连接时用户所在网络能看到门户域名 |
| 拉回的内容与「导入文件」走同一个导入器 | 两种方式交付的是同一份文档 |
| 没有定时自动更新，用户对配置点「更新」才重新拉取 | 页面写明需要手动「更新」 |

## 6. 版本演进

增加、删除或改变任何键或规则，都是新版本，并在本目录新增规范与金样。门户拒绝它不认识的版本。

第 1 版写于 2026-11-06，从未部署，也没有导入过真实配置包。它与第 2 版的区别：

| | 第 1 版 | 第 2 版 |
|---|---|---|
| 配置包里有谁 | Mooring 全部应被服务的用户，包括没绑定门户账号的 | 运营者点名的用户，也就是全部已绑定用户 |
| 不交付的用户 | 不出现 | 写进 `withheld`，带原因 |
| 已绑定账号的用户不在配置包里 | 当作停止服务：删除配置，停用订阅链接 | 当作漏列：整份拒绝，什么也不改 |
| `profiles` | 至少一项 | 可以为空，但至少点名一个用户 |

门户只读第 2 版。第 1 版的配置包（例如 Mooring main `d478e91` 的导出器写出的）报"version 1"，什么也不写（金样 `invalid/version-1.json` 就是第 1 版的合法样例）。门户的数据库不记录配置包的版本，第 1 版又从未部署，所以不需要迁移，也不保留读第 1 版的代码。

## 7. Mooring 一侧的导出器

第 1 版的导出器已在 Mooring 实现：PR #24，2026-11-06 合并为 main `d478e91`，命令是 `mooringctl user export-profiles --out <文件>`。第 2 版要求它这样改：

- **运营者点名**：`--user <id>` 可重复，至少一个，不再导出全部用户，和快照导出器一样。名单为空、有重复，或有 Mooring 不认识的编号（多半是抄错了），都让整次导出失败、不写文件。`--user` 写用户编号，不写别名，配置包里也只写编号（门户拒绝别名）。
- 名单从门户取：`mooring-portal --db <文件> bound-users` 按编号顺序输出一行 `--user <编号> --user <编号> …`，正是全部已绑定账号的用户，可以直接接在导出命令后面（编号只含小写字母和数字 2–7，不用加引号）。被暂停的用户也在名单里，不必为此解绑。
- 每个点名的用户在配置包里出现，而且只出现一次：
  - `Active`、并且接受了当前版本《使用约定》的用户进 `profiles`，文档照旧用 `ExportFormat::SingBoxJson` 生成；
  - 其余的进 `withheld`：被暂停的写 `suspended`；作废中、已作废的写 `revoked`；状态正常、但还没接受当前版本《使用约定》的写 `agreement_not_accepted`。命令照旧逐个列出他们。归类要穷尽，每一种状态都明确对应一边，不用兜底分支：Mooring 以后新增状态时，先改本契约；
  - 应被服务、却生成不了文档的用户（节点还没 apply、证书过期等）照旧让整次导出失败。
- 所以配置包要么恰好是点名的这些用户，要么不写文件。条目的顺序不限，门户不依赖顺序；金样按编号排列。
- 点名的用户全都不交付时，照样写出配置包（`profiles` 为空，金样 `valid/all-withheld.json`）：门户要据此停止服务他们。
- 《使用约定》写明门户之前（Mooring 的 `PORTAL_AGREEMENT_SINCE` 还没设置，它随《使用约定》第 2 版设置），整次导出失败、不写文件，**而不是**把所有人写成 `agreement_not_accepted`：那样的配置包是合法的，导入后会停用每一个已绑定账号的订阅链接。
- 输出文件以 0600 创建，导入门户后删除。
- 金样测试按键名、键的顺序和值的类型，与本目录的 `valid/pilot.json`、`valid/all-withheld.json` 对照；条目的顺序不必一致。

《使用约定》升版后，还没重新确认的已绑定用户会进 `withheld`，导入后他们的订阅链接停用、不再恢复。所以要等全部已绑定用户重新确认后再导出（Mooring 交付手册第 11 节）。

## 8. 与《使用约定》的关系

《Mooring 使用约定》第 1 版写明"凭据从不上联网的服务器"的交付方式（第 2 条：不要把任何链接粘贴到聊天；第 5 条：本服务没有订阅链接）。门户保存配置包，就把已绑定用户的节点凭据放到了一台联网主机上，并引入了链接。**导入真实用户的配置包之前，须修订使用约定并请用户重新确认**：写明门户保存什么（第 4 条）、订阅链接怎么用、怎么保管、泄露时怎么办（第 2、5 条）。没有门户账号的用户不进配置包，第 1 版"凭据不上联网主机"的承诺对他们不变。
